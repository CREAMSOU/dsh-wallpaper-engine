# ADR-0016: 代码即真相，文档只引用源码位置（Code is truth; docs reference source）

- **Date**: 2026-10-27
- **Status**: Accepted
- **Deciders**: YV3507
- **Supersedes**: [ADR-0006](./0006-comment-discipline-as-written-convention.md)（注释/文档的写作约定与"撤除文档守卫"作为审阅纪律的部分）
- **Amends**: [ADR-0007](./0007-machine-checks-target-code-not-prose.md) 的 `Depends on` 关系（其"机器判据只针对代码与磁盘"仍有效）

## Context

仓库的文档系统在长期维护中形成了两套负担：

1. **文档复制源码**：架构、模块清单、默认值、条数、路由族、工具名册被写进 markdown，
   代码一改就要同步改文档；不同步就会漂。ADR-0006 的结论本来就是"文档类守卫已撤除、靠写作约定"，
   但写作约定本身仍要求作者与评审维护大量**与代码同构的散文**。
2. **文档改动被当成代码改动审阅**：ADR-0006 把"注释 / 文档 / 账本"的写法上升为需要评审的约定，
   而实际评审很难判断一句原理说明是否准确；结果是评审精力花在措辞上，而不是代码上。

同时，仓库已经有一套更可靠的机制：机制与不变量写在**实现文件头注释**；机器事实写成**守卫**；
取舍写成 ADR；生成物（`ROUTE-INDEX.md` / `GUARD-MAP.md` / `TOKEN-CONTRACT.md`）由工具重算并逐字节校验。
这些都比手工维护的散文更接近真相。

## Decision

**代码（含生成物、守卫、实际运行结果）是唯一真相；文档是索引与解释，不是第二份实现。**

- **D1 — 原理说明引用源码，不复制源码。** 需要解释机制时，指向 `路径:符号` / 函数名 / 文件头注释 /
  复算命令，而不是把代码、清单、默认值、条数、行数、路由表抄进文档。文档里出现会随代码漂的值，
  视为文档的缺陷而不是必须维护的承诺。
- **D2 — 文档只保留三类内容。**
  1. 决策与代价（`adr/`）；
  2. 用户可见行为的"为什么/怎么用"（README、UPGRADING、TROUBLESHOOTING、HOW-IT-WORKS 等）；
  3. 由工具生成、逐字节校验的契约索引（ROUTE-INDEX / GUARD-MAP / TOKEN-CONTRACT）。
  人工维护的架构快照、工具名册、进度账本不再作为必维护项；保留的旧文档以"可能滞后、以代码为准"标注。
- **D3 — 取消针对文档的代码审查与文档类门禁。** 不要求代码改动同步更新文档，不要求文档改动
  做机器判定（docs 快通道只做冲突标记/断链/素材等轻量检查）；评审可以建议改文档，但不能因
  "文档没同步"阻塞合并。ADR-0006 的写作约定/审阅约束由本 ADR 取代。
- **D4 — 冲突时以代码为准。** 文档与代码不一致时，修文档是顺手的事，不是 CI 失败项；
  历史归档与 `CHANGELOG.md` 是账本，不追溯改写。
- **D5 — 删减优先于维护。** 发现某份文档主要是源码的副本、且已漂移，优先删除或归档，
  只留一句指向源码的索引；不为它们新增守卫、不为它们补测试。

## Consequences

**收益**

- **评审回到代码**：不再需要评审一句原理说明是否"措辞正确"。
- **文档不会因代码演进被迫同步**：索引式文档天然稳定，漂了也只是链接过时，不是事实错误。
- **仓库变轻**：人工快照/名册/账本可以归档或删除，减少 76 份 markdown 的维护面。

**代价**

- 想知道细节必须读源码（这是有意选择：源码是唯一不会撒谎的地方）。
- 旧文档可能滞后；靠"看到就改"而不是机器保证。
- 若将来某类文档漂移造成实际误导，应该把该事实改成**代码旁的注释 / 生成物 / 守卫**，
  而不是恢复文档评审或新增散文判据（触发线见 ADR-0007 的四问）。

## 重新考虑的触发线

- 某个"引用源码"的文档因为源码移动导致链接大面积失效，且读者确实因此被误导 ⇒ 先考虑生成
  （从源码派生的索引），而不是手工维护。
- 文档删减后出现"找不到任何决策记录"的情况 ⇒ 补 ADR，不补散文。
